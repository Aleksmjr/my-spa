## Техническое задание ### Общие требования 1. **Стек:** HTML, CSS, JS. 2. Запрещено использовать: - Библиотеки. - Шаблонизаторы. - Препроцессоры. 3. HTML-документ должен содержать только обязательные теги и `
`. 4. Выходная разметка должна быть семантически корректной и проходить проверку валидатором. 5. Необходима методология БЭМ в именовании классов. 6. JavaScript-код должен быть структурированным и модульным. ### Входные данные 1. Данные о постах и пользователях должны быть получены от сервиса [JSONPlaceholder](https://jsonplaceholder.typicode.com/). - Запросы: - **Массив постов:** `/posts` - **Массив пользователей:** `/users` - **Структура объектов постов:** - `title` (заголовок). - `body` (текст). - `userId` (ID автора). - `id` (ID поста). - **Структура объектов пользователей:** - `id` (ID пользователя). - `name` (имя). - `email` (почта). 2. **Динамическая генерация даты публикации:** - Для каждого поста на клиенте должно быть добавлено новое свойство `date`. - **Условия для даты:** - Формат: количество миллисекунд с начала эпохи Unix. - Диапазон дат: с 1 января 2010 года по 31 декабря 2020 года. - Дата должна быть случайной в указанном диапазоне. ### Функциональные требования 1. **Одностраничное приложение (SPA).** 2. **Список постов:** - При загрузке страницы посты отображаются в исходном порядке (без сортировки). - Посты загружаются порциями по 5 штук (бесконечная подгрузка). Новая порция загружается при достижении конца текущего списка. - Если размер последней порции из API меньше 5 постов, она должна быть дополнена постами из `localStorage`. 3. **Работа с LocalStorage:** - Все посты, созданные пользователем, должны сохраняться в `localStorage` в формате JSON. - При обновлении страницы посты из `localStorage`: - Загружаются в список последними. - Подгружаются так же порциями по 5 постов, пока не закончатся. 4. **Поповер:** - Клик по имени автора вызывает поповер с информацией: - ID. - Имя. - Email. 5. **Сортировка:** - Реализовать сортировку постов по дате публикации в обе стороны (по возрастанию и убыванию). - Посты, созданные через форму, добавляются: - **В начало списка**, если сортировка по умолчанию (без сортировки). - **В соответствии с текущей сортировкой**, если она активна (по возрастанию или убыванию даты). 6. **Форма добавления поста:** - Форма должна быть реализована в модальном окне. - Открытие формы выполняется по кнопке "Добавить пост". - Форма должна позволять создать новый пост. - Автором добавленных постов всегда является "admin". - Все свойства поста обязательны, включая: - Заголовок (не длиннее 30 символов). - Текст (не менее 30 символов). - Дату публикации (текущее время в миллисекундах). - ID автора. - ID поста (генерируется уникально). - Форма должна проверять, что все поля заполнены. - При успешном добавлении поста: - Новый пост сохраняется в `localStorage`. - Модальное окно закрывается. - Пост добавляется в начало списка или в соответствии с текущей сортировкой. 7. **Удаление постов:** - Реализовать возможность удаления постов. - Удаление доступно только для администратора. - При попытке удалить пост должно появляться модальное окно с подтверждением. - В модальном окне: - Сообщение, например: "Вы уверены, что хотите удалить пост?" - Кнопки "Удалить" и "Отмена". - Кнопка "Удалить" удаляет пост, а "Отмена" закрывает окно. - Если удаляемый пост находится в `localStorage`, он также удаляется оттуда. 8. **Формат даты для отображения:** - В интерфейсе даты публикации отображаются в формате "12 декабря 2014 года". 9. **Информация о текущем пользователе:** - В хедере страницы отображается имя текущего пользователя (администратора). 10. **Анимации:** - Реализовать плавные анимации для: - Добавления поста. - Удаления поста. - Открытия поповера. - Переключения сортировки. - Открытия и закрытия модальных окон. 11. **Адаптивная верстка:** Приложение должно корректно отображаться на устройствах с разными разрешениями экрана. 12. **Модальное окно для формы добавления поста:** - Должно перекрывать основной контент и иметь затемнённый фон. - Содержать: - Поля ввода для всех обязательных свойств поста. - Кнопки "Добавить" и "Отмена". - Кнопка "Добавить" добавляет новый пост, а "Отмена" закрывает окно. 13. **Модальное окно для подтверждения удаления:** - Должно перекрывать основной контент и иметь затемнённый фон. - Содержать сообщение с вопросом: "Вы уверены, что хотите удалить пост?" - Кнопки "Удалить" и "Отмена". ## План реализации проекта ### 1.
